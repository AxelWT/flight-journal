## 一、指针的本质

`&` 是取地址符号，`*` 是根据地址取值符号。指针这个变量存的是地址，普通变量存的是地址上的值。

> 在最常见的一层指针场景下，这个结论是标准答案；多层指针场景下，注意指针也是变量，也有自己的地址。

```cpp
int a = 42;      // 普通变量 a，存的是值 42
int *p = &a;     // 指针变量 p，存的是 a 的地址

std::cout << p;  // p 本身就是地址
std::cout << *p; // 根据地址取值，输出 42
```

## 二、函数的几种传参方式

```cpp
void f1(std::string s);        // 按值传递：发生拷贝，浪费
void f2(std::string &s);       // 按引用：无拷贝，但函数内可修改原字符串
void f3(const std::string &s); // 常量引用：无拷贝，且只读，最适合读参数
```

注意 `f2` 这种非 const 引用不能传字符串字面量（字面量是右值），而 `const std::string &s` 可以绑定右值，所以既能传变量也能传字面量。

## 三、字节序

CPU 在内存中存多字节数值时，字节的排列顺序就是字节序。同样一个 32 位整数 `0x0102A8C0`，两种机器存法不同：

**小端（Little-Endian）**：低位字节放低地址

```text
内存地址：  低 ────→ 高
字节：     C0  A8  02  01
```

**大端（Big-Endian）**：高位字节放低地址

```text
内存地址：  低 ────→ 高
字节：     01  02  A8  C0
```

> 大端的好处是：从左往右读内存 = 人类读数字的习惯（高位在前），网络协议传输字节流就采用大端，所以大端也叫**网络字节序**。

常见机器的字节序：

| 类型 | 字节序 | 典型代表 |
|---|---|---|
| 小端 | x86、x86-64 | Intel/AMD CPU、几乎所有 PC 和服务器（包括你现在的电脑） |
| 小端 | ARM（默认） | Apple M 系列、绝大多数手机、鲲鹏/飞腾（国产化场景常见） |
| 大端 | 部分 MIPS、PowerPC | 传统网络设备、部分嵌入式/大型机 |

> ARM 是小端为主，但硬件上支持切换成大端模式（BIER、某些网络芯片会用）。日常开发中 99% 接触的都是小端。

判断当前机器是哪种字节序：

```cpp
uint32_t x = 1;
if (*(uint8_t*)&x == 1) {
    // 小端：低地址存的是低位字节 0x01
}
```

在小端机器上把 `192.168.1.1` 转成整数 `0x0101A8C0`，它在内存里正好是 `C0 A8 01 01`——与 IP 报文中字节的原始顺序一致，可以直接用于网络填充。这就是为什么这个函数在 x86/ARM 上工作正常，但如果代码跑在大端机器上，字节布局就会和预期相反，需要加转换。这也解释了为什么很多 C++ 项目里都有 `htons()`/`htonl()`/`ntohl()` 这类"主机序 ↔ 网络序"转换函数。
